========================================
음성 검색 기능 추가 가능 여부 검토
(제어권이 모바일인 경우 검색 왼쪽에 음성 검색 버튼)
========================================

## 1. 현재 상황 분석

### 1.1. 제어권 관리 현황
- 제어권(hasControl)은 서버에서 관리됨
- 서버는 제어권을 가진 세션의 socket.id만 추적
- 제어권을 가진 클라이언트가 모바일인지 데스크톱인지는 현재 구분하지 않음

### 1.2. 현재 검색 UI 구조
- MusicRequestForm 컴포넌트에 텍스트 입력 필드와 검색 버튼만 존재
- 음성 검색 기능은 현재 구현되어 있지 않음
- 검색 입력 필드 왼쪽에 버튼을 추가할 공간은 있음 (CSS flex 레이아웃)

### 1.3. 서버에서 수집하는 정보
- 서버는 클라이언트 연결 시 user-agent 정보를 수집함
  * server/index.js의 clientInfo에 userAgent 저장
  * 하지만 이 정보는 클라이언트에게 전달되지 않음

## 2. 음성 검색 기능 추가 가능 여부

### 2.1. 기술적 가능성: ✅ 가능

#### [가능한 이유]
1. **Web Speech API 지원**
   - 브라우저에서 음성 인식을 위한 Web Speech API 사용 가능
   - SpeechRecognition API (Chrome, Edge, Safari 등 지원)
   - 모바일 브라우저에서도 지원됨

2. **UI 배치 가능**
   - 현재 input-group이 flex 레이아웃으로 구성됨
   - 검색 입력 필드 왼쪽에 음성 검색 버튼 추가 가능
   - CSS 수정으로 레이아웃 조정 가능

3. **제어권 정보 활용 가능**
   - App.js에서 hasControl 상태를 MusicRequestForm에 props로 전달 가능
   - 제어권이 있는지 여부는 이미 클라이언트에서 알 수 있음

### 2.2. 모바일 감지 방법

#### [방법 1] 서버에서 user-agent 전달 (권장)
- 서버가 이미 user-agent를 수집하고 있음
- 클라이언트 연결 시 user-agent를 클라이언트에 전달
- 클라이언트에서 user-agent를 파싱하여 모바일 여부 판단

**구현 예시:**
```javascript
// server/index.js
socket.emit('currentState', {
  currentPlaying,
  queue: queueManager.getQueue(),
  isPlaying,
  isAdmin: isAdmin,
  hasControl: hasControl,
  userAgent: clientInfo.userAgent  // 추가
});

// client/src/App.js
const [isMobile, setIsMobile] = useState(false);

socket.on('currentState', (data) => {
  // user-agent로 모바일 감지
  const mobileRegex = /Android|webOS|iPhone|iPad|iPod|BlackBerry|IEMobile|Opera Mini/i;
  setIsMobile(mobileRegex.test(data.userAgent || navigator.userAgent));
});
```

#### [방법 2] 클라이언트에서 직접 감지 (간단)
- 브라우저의 navigator.userAgent로 직접 감지
- 서버 수정 불필요

**구현 예시:**
```javascript
// client/src/App.js 또는 MusicRequestForm.jsx
const isMobile = /Android|webOS|iPhone|iPad|iPod|BlackBerry|IEMobile|Opera Mini/i
  .test(navigator.userAgent);
```

#### [방법 3] 제어권 보유 클라이언트의 user-agent 확인 (정확)
- 서버에서 제어권을 가진 세션의 user-agent를 모든 클라이언트에 브로드캐스트
- 모든 클라이언트가 "제어권이 모바일에 있는지" 알 수 있음

**구현 예시:**
```javascript
// server/index.js
function broadcastControlStatus() {
  const controlUserAgent = controlSessionId 
    ? connectedClients.get(controlSessionId)?.userAgent 
    : null;
  
  io.sockets.sockets.forEach((sock) => {
    const clientInfo = connectedClients.get(sock.id);
    if (clientInfo && clientInfo.isAdmin) {
      const hasControl = controlSessionId === sock.id;
      clientInfo.hasControl = hasControl;
      sock.emit('controlStatus', { 
        hasControl: hasControl,
        controlUserAgent: controlUserAgent  // 추가
      });
    }
  });
}

// client/src/App.js
const [controlIsMobile, setControlIsMobile] = useState(false);

socket.on('controlStatus', (data) => {
  setHasControl(data.hasControl || false);
  if (data.controlUserAgent) {
    const mobileRegex = /Android|webOS|iPhone|iPad|iPod|BlackBerry|IEMobile|Opera Mini/i;
    setControlIsMobile(mobileRegex.test(data.controlUserAgent));
  }
});
```

### 2.3. 음성 검색 구현 방법

#### [Web Speech API 사용]
```javascript
// client/src/components/MusicRequestForm.jsx
const [isListening, setIsListening] = useState(false);
const recognitionRef = useRef(null);

useEffect(() => {
  // Web Speech API 초기화
  if ('webkitSpeechRecognition' in window || 'SpeechRecognition' in window) {
    const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition;
    recognitionRef.current = new SpeechRecognition();
    recognitionRef.current.continuous = false;
    recognitionRef.current.interimResults = false;
    recognitionRef.current.lang = 'ko-KR'; // 한국어
    
    recognitionRef.current.onresult = (event) => {
      const transcript = event.results[0][0].transcript;
      setQuery(transcript);
      setIsListening(false);
      // 자동 검색 실행 (선택사항)
      // handleSubmit({ preventDefault: () => {} });
    };
    
    recognitionRef.current.onerror = (event) => {
      console.error('음성 인식 오류:', event.error);
      setIsListening(false);
      alert('음성 인식 중 오류가 발생했습니다.');
    };
    
    recognitionRef.current.onend = () => {
      setIsListening(false);
    };
  }
  
  return () => {
    if (recognitionRef.current) {
      recognitionRef.current.stop();
    }
  };
}, []);

const handleVoiceSearch = () => {
  if (!recognitionRef.current) {
    alert('이 브라우저는 음성 인식을 지원하지 않습니다.');
    return;
  }
  
  if (isListening) {
    recognitionRef.current.stop();
    setIsListening(false);
  } else {
    recognitionRef.current.start();
    setIsListening(true);
  }
};
```

#### [UI 추가]
```jsx
// MusicRequestForm.jsx의 input-group 부분
<div className="input-group">
  {/* 음성 검색 버튼 (제어권이 모바일일 때만 표시) */}
  {hasControl && controlIsMobile && (
    <button
      type="button"
      onClick={handleVoiceSearch}
      className={`voice-search-btn ${isListening ? 'listening' : ''}`}
      disabled={isLoading}
      title="음성으로 검색"
    >
      {isListening ? '🎤 듣는 중...' : '🎤'}
    </button>
  )}
  
  <input
    type="text"
    value={query}
    onChange={(e) => setQuery(e.target.value)}
    placeholder="음악 제목 또는 아티스트 이름을 입력하세요..."
    disabled={isLoading}
    className="music-input"
  />
  
  <button 
    type="submit" 
    disabled={!query.trim() || isLoading}
    className="submit-btn"
  >
    {isLoading ? '검색 중...' : '검색'}
  </button>
</div>
```

## 3. 구현 시 고려사항

### 3.1. 브라우저 호환성
- ✅ Chrome/Edge: SpeechRecognition API 지원
- ✅ Safari (iOS 14.5+): SpeechRecognition API 지원
- ⚠️ Firefox: 지원하지 않음 (폴백 필요)
- ⚠️ 일부 구형 브라우저: 지원하지 않을 수 있음

### 3.2. 권한 요청
- 음성 인식 사용 시 마이크 권한 요청 필요
- 사용자가 권한을 거부할 수 있음
- 권한 거부 시 안내 메시지 표시 필요

### 3.3. 제어권 이동 시 처리
- 제어권이 모바일 → 데스크톱으로 이동 시
  * 음성 검색 버튼이 사라져야 함
- 제어권이 데스크톱 → 모바일로 이동 시
  * 음성 검색 버튼이 나타나야 함
- controlStatus 이벤트로 실시간 업데이트 가능

### 3.4. UI/UX 고려사항
- 음성 검색 버튼은 검색 입력 필드 왼쪽에 배치
- 버튼 크기는 모바일 터치에 적합하게 (최소 44x44px)
- 듣는 중일 때 시각적 피드백 제공 (애니메이션, 색상 변경)
- 음성 인식 중일 때는 검색 버튼 비활성화
