========================================
AI 추천 검색 기능 구현 시나리오
(대기열 하트 높은 순 기반 추천)
========================================

1. 개요
----------------------------------------
현재 대기열에 있는 음악들 중 하트(좋아요)가 높은 순으로 정렬하여,
그 음악들의 특징을 분석하고 유사한 음악을 추천하는 AI 검색 기능

목표:
- 대기열의 인기 음악 패턴 분석
- 사용자 선호도 기반 음악 추천
- 브라우저에서 직접 실행 가능한 ML 모델 활용 (Transformers.js)
- 실시간 추천 결과 제공 (서버 부하 없음)
- 오프라인 동작 가능 (모델 캐싱 후)

2. 데이터 수집 및 전처리
----------------------------------------
2.1. 대기열 데이터 수집
    - 현재 대기열(queue)의 모든 음악 정보 수집
      * videoId
      * title (제목)
      * thumbnail (썸네일)
      * requestedBy (요청자)
      * 추가된 시간
    
2.2. 하트 데이터 수집
    - musicLikes Map에서 각 음악의 좋아요 개수 조회
    - 대기열의 각 음악에 대해:
      * videoId로 좋아요 개수 조회
      * 좋아요 개수가 0인 음악도 포함 (가중치 낮게)
    
2.3. 데이터 정렬
    - 좋아요 개수 기준 내림차순 정렬
    - 좋아요 개수가 같으면 추가된 시간 기준 (최신순)
    - 상위 N개 선택 (예: 상위 5~10개)
      * 대기열이 적으면 전체 사용
      * 대기열이 많으면 상위 10개만 사용
    
2.4. 특징 추출을 위한 데이터 준비
    - 선택된 음악들의 제목(title) 수집
    - YouTube API 또는 추가 메타데이터에서:
      * 아티스트 이름 추출
      * 장르 정보 (가능한 경우)
      * 발행 연도 (가능한 경우)
      * 재생 시간 (가능한 경우)

3. 머신러닝 모델 선택 및 적용
----------------------------------------
3.1. 브라우저 실행 환경 제약사항
    - 메모리 제한: 브라우저별 다름 (일반적으로 2-4GB)
    - 네트워크: 모델 다운로드 시간 고려 (초기 1회)
    - IndexedDB: 모델 캐싱을 위한 저장 공간 필요
    - WebAssembly: 모델 실행을 위한 WASM 지원 필요
    - 크로스 브라우저 호환성: Chrome, Firefox, Safari, Edge 지원

3.2. 선택된 모델: Xenova/multilingual-e5-small
    - 라이브러리: @xenova/transformers (Transformers.js)
    - 모델: Xenova/multilingual-e5-small
    - 크기: ~40MB (다운로드, IndexedDB 캐싱)
    - 속도: 매우 빠름 (~50-100ms/텍스트, 브라우저에서)
    - 한국어 지원: ⭐⭐⭐⭐⭐ (multilingual 모델)
    - 특징:
      * Hugging Face 모델을 브라우저에서 직접 실행
      * WebAssembly 기반으로 빠른 추론
      * 오프라인 동작 가능 (모델 캐싱 후)
      * 서버 부하 없음 (클라이언트에서 실행)
      * 실시간 처리 가능

3.3. 모델 로딩 전략
    - 첫 로드 시:
      * 모델 파일 다운로드 (~40MB)
      * IndexedDB에 캐싱
      * 로딩 시간: 약 5-10초 (네트워크 속도에 따라)
    - 이후 로드:
      * IndexedDB에서 즉시 로드
      * 로딩 시간: 약 1-2초
    - 캐싱 전략:
      * 전역 변수에 모델 인스턴스 저장
      * 페이지 새로고침 시 IndexedDB에서 복원
      * 캐시 만료: 없음 (수동 삭제 전까지 유지)
    - 로딩 상태 표시:
      * 첫 로드: "AI 모델 로딩 중... (5-10초 소요)"
      * 캐시 로드: "AI 모델 준비 중... (1-2초 소요)"
      * 로드 완료: "AI 추천 준비 완료"

3.4. 하이브리드 추천 접근 (권장)
    - 1단계: 텍스트 유사도 (제목, 아티스트)
      * Xenova/multilingual-e5-small로 음악 제목 임베딩
      * 상위 하트 음악들의 가중 평균 임베딩 계산
      * 좋아요 개수로 가중치 적용
    - 2단계: 통계적 필터링
      * 같은 아티스트 음악 가중치 증가 (+15%)
      * 인기도 보너스 (+15%)
    - 3단계: 최종 점수 계산
      * 텍스트 유사도 점수 (70%)
      * 아티스트 일치 점수 (15%)
      * 인기도 보너스 점수 (15%)
      * 최종 점수로 정렬

3.5. 인기도 확인 방법
    [방법 1] YouTube Data API 조회수 (1순위, 권장)
    - YouTube Data API v3 사용
    - videoId로 조회수(viewCount) 가져오기
    - 발행 날짜(publishedAt)도 함께 가져오기
    - 인기도 점수 계산:
      * 조회수 정규화: log(viewCount + 1) / log(maxViewCount + 1)
      * 최신도 보너스: 최근 발매일수록 가중치 증가
      * 최종 인기도 점수 = 조회수 점수 × 0.7 + 최신도 점수 × 0.3
    - 장점:
      * 정확한 인기도 반영
      * 조회수 기반으로 객관적 평가
    - 단점:
      * YouTube Data API 키 필요
      * 추가 API 호출 발생
      * API 할당량 제한 고려 필요
    
    [방법 2] YouTube 검색 결과 순서 (2순위, 폴백)
    - YouTube 검색 API 결과의 순서를 인기도로 간주
    - 검색 결과는 기본적으로 인기순으로 정렬됨
    - 인기도 점수 계산:
      * 검색 결과 1-3위: 1.0 (최고 인기)
      * 검색 결과 4-5위: 0.9
      * 검색 결과 6-10위: 0.7
      * 검색 결과 11-20위: 0.5
      * 검색 결과 21위 이후: 0.3
    - 장점:
      * 추가 API 호출 불필요
      * 구현 간단
      * API 키 불필요
    - 단점:
      * 정확도가 상대적으로 낮음
      * 검색어에 따라 순서가 달라질 수 있음
    
    [구현 전략]
    - 1순위: YouTube Data API 사용 시도
      * API 키가 있으면 조회수 기반 인기도 사용
      * videoId로 videos.list API 호출
      * statistics.viewCount, snippet.publishedAt 사용
    - 2순위: API 키가 없거나 실패 시
      * 검색 결과 순서 기반 인기도 사용
      * 검색 결과의 index를 인기도 점수로 변환
    - 폴백: 두 방법 모두 실패 시
      * 인기도 점수 = 0.5 (기본값)
      * 또는 인기도 보너스 제외

4. 추천 알고리즘 시나리오
----------------------------------------
4.1. 입력 데이터 준비
    Step 1: 대기열에서 하트 높은 순 정렬
      queue = [
        { id: "1", videoId: "abc123", title: "노래1", likeCount: 5 },
        { id: "2", videoId: "def456", title: "노래2", likeCount: 3 },
        { id: "3", videoId: "ghi789", title: "노래3", likeCount: 2 },
        ...
      ]
      → 상위 5개 선택
    
    Step 2: 선택된 음악들의 특징 벡터 생성
      topSongs = [
        { title: "노래1", likeCount: 5, embedding: [0.1, 0.2, ...] },
        { title: "노래2", likeCount: 3, embedding: [0.3, 0.1, ...] },
        ...
      ]
    
    Step 3: 가중 평균 임베딩 계산
      weightedEmbedding = Σ(song.embedding * song.likeCount) / Σ(likeCount)
      → 사용자 선호도 반영된 평균 벡터

4.2. 추천 검색 실행
    Step 1: 사용자 검색어 입력
      - 사용자가 "비슷한 노래 추천해줘" 또는 "AI 추천" 버튼 클릭
      - 검색어가 있으면 검색어도 함께 고려
    
    Step 2: YouTube 검색 실행
      - 가중 평균 임베딩과 유사한 음악 검색
      - 또는 상위 하트 음악들의 키워드 조합으로 검색
        예: "노래1 아티스트 OR 노래2 아티스트 OR ..."
    
    Step 3: 검색 결과 임베딩 및 유사도 계산
      searchResults = YouTube API 검색 결과
      for each result in searchResults:
        result.embedding = 모델.encode(result.title)
        result.similarity = cosine_similarity(
          weightedEmbedding, 
          result.embedding
        )
    
    Step 4: 인기도 점수 계산
      [방법 1] YouTube Data API 사용 (1순위)
        for each result in searchResults:
          videoDetails = YouTube Data API로 조회수 가져오기
          viewCount = videoDetails.statistics.viewCount
          publishedAt = videoDetails.snippet.publishedAt
          
          // 조회수 정규화 (로그 스케일)
          normalizedViewCount = log(viewCount + 1) / log(maxViewCount + 1)
          
          // 최신도 계산 (최근 발매일수록 높음)
          daysSincePublished = (현재날짜 - publishedAt) / (365 * 24 * 60 * 60 * 1000)
          recencyScore = Math.max(0, 1 - daysSincePublished / 2) // 2년 이내
          
          // 인기도 점수
          popularityScore = normalizedViewCount * 0.7 + recencyScore * 0.3
      
      [방법 2] 검색 결과 순서 사용 (2순위, 폴백)
        for each result in searchResults:
          index = result의 검색 결과 순위 (0부터 시작)
          if (index < 3): popularityScore = 1.0
          else if (index < 5): popularityScore = 0.9
          else if (index < 10): popularityScore = 0.7
          else if (index < 20): popularityScore = 0.5
          else: popularityScore = 0.3
    
    Step 5: 최종 점수 계산 및 정렬
      for each result in searchResults:
        score = (
          similarity * 0.7 +           // 텍스트 유사도 (70%)
          artistMatch * 0.15 +          // 아티스트 일치 (15%)
          popularityScore * 0.15       // 인기도 보너스 (15%)
        )
      → score 기준 내림차순 정렬
    
    Step 6: 상위 N개 반환
    
      - 상위 10~20개 추천 결과 반환
      - 이미 대기열에 있는 음악 제외
      - 중복 제거

7. 성능 최적화
----------------------------------------
7.1. 모델 로딩 최적화
    - IndexedDB에 모델 캐싱
      * 첫 다운로드 후 영구 저장
      * 페이지 새로고침 시에도 유지
      * 수동 삭제 전까지 재사용
    - 전역 변수에 모델 인스턴스 캐싱
      * 한 번 로드하면 메모리에 유지
      * 여러 추천 요청 시 재사용
    - 백그라운드 로딩
      * 앱 시작 시 미리 로드 (선택사항)
      * 사용자가 버튼 클릭 전에 준비

7.2. 캐싱 전략
    - 모델 캐싱: IndexedDB에 영구 저장
      * 키: 'ai-model-xenova-multilingual-e5-small'
      * 크기: ~40MB
      * 만료: 없음 (수동 삭제)
    - 추천 결과 캐싱: 메모리 또는 localStorage
      * 캐시 키: 대기열 해시 (videoId 정렬 후 해시)
      * TTL: 5분
      * 크기 제한: 최대 10개 결과 세트
    - 임베딩 캐싱: 메모리
      * 같은 제목의 임베딩은 재사용
      * Map 구조로 관리

7.3. 비동기 처리
    - 모델 로딩과 데이터 수집을 병렬 처리
    - 임베딩 생성은 순차 처리 (메모리 절약)
    - YouTube 검색은 서버에서 처리 (API 제한 고려)
    - UI 업데이트는 requestAnimationFrame 사용

7.4. 폴백 전략
    - 모델 로딩 실패 시:
      * 키워드 기반 검색으로 대체
      * 상위 하트 음악들의 키워드 조합으로 YouTube 검색
      * 사용자에게 "AI 모델 로딩 실패, 키워드 기반 검색 사용" 알림
    - 모델 다운로드 실패 시:
      * 네트워크 오류 메시지 표시
      * 재시도 버튼 제공
    - 추천 결과가 없을 때:
      * 일반 YouTube 검색 결과 반환
      * "추천 결과가 없습니다. 일반 검색 결과를 표시합니다." 메시지

      * videos.list API로 조회수, 발행일 가져오기
      * ↓
      * [클라이언트] 조회수 + 발행일 기반 점수 계산
      * 조회수 정규화 + 최신도 보너스
    - 방법 2: 검색 결과 순서 기반 (2순위, 폴백)
      * API 키가 없거나 실패 시 사용
      * 검색 결과 index를 점수로 변환
      * 1-3위: 1.0, 4-5위: 0.9, 6-10위: 0.7, ...
    ↓
  유사도 계산 (브라우저에서)
    - 각 검색 결과 제목 → 임베딩 벡터
    - 코사인 유사도 계산 (평균 임베딩과 비교)
    - 아티스트 일치 점수 계산
    ↓
  최종 점수 계산 (브라우저에서)
    - 유사도(0.7) + 아티스트(0.15) + 인기도(0.15)
    ↓
  정렬 및 필터링 (브라우저에서)
    - 점수 기준 내림차순 정렬
    - 대기열 중복 제거 (videoId 비교)
    - 상위 10~20개 선택
    ↓
  추천 결과 UI 표시
    - RecommendationModal 컴포넌트에 표시
    - 추천 이유, 처리 시간 등 표시
    ↓
  사용자가 추천 음악 선택
    ↓
  대기열에 추가 요청
    socket.emit('addToQueue', {...})

12. 주의사항 및 제약사항
----------------------------------------
12.1. 브라우저 환경 제약
    - 초기 모델 다운로드: 첫 사용 시 5~10초 소요 (네트워크 속도에 따라)
    - 메모리 사용: 모델 로드 시 ~100-200MB 메모리 사용
    - IndexedDB 용량: 모델 캐싱을 위해 ~40MB 저장 공간 필요
    - 브라우저 호환성: WebAssembly 지원 필요 (최신 브라우저)
    - 네트워크: 오프라인 모드에서는 모델 다운로드 불가 (캐시 후 가능)

12.2. 데이터 품질
    - 대기열이 비어있거나 적을 때 추천 품질 저하
    - 하트가 없는 음악만 있을 때 추천 어려움
    - 해결: 최소 데이터 요구사항 설정 (예: 최소 3개 음악, 최소 1개 하트)

12.3. YouTube API 제한
    - YouTube Data API: 일일 할당량 제한 (기본 10,000 units/일)
      * videos.list 호출: 1 unit
      * 인기도 확인을 위한 추가 호출 발생
      * 해결: 배치 처리, 결과 캐싱
    - YouTube Search API: 일일 할당량 제한
      * 검색 결과 품질 의존
      * 해결: 결과 캐싱, 검색어 최적화
    - API 키 없을 때: 검색 결과 순서 기반 인기도 사용 (폴백)

12.4. 모델 한계
    - 한국어 음악 제목 처리 능력
    - 장르 특화 정보 부족
    - 해결: 다국어 모델 사용 또는 한국어 특화 모델

    파일: client/src/services/similarityCalculator.js
    작업 내용:
    1. SimilarityCalculator 클래스 생성
    
    2. cosineSimilarity(vec1, vec2) 메서드 구현
       - 두 벡터의 코사인 유사도 계산
       - 공식: dot(vec1, vec2) / (norm(vec1) * norm(vec2))
    
    3. calculateWeightedAverage(embeddings, weights) 메서드 구현
       - 가중 평균 임베딩 계산
       - 좋아요 개수를 가중치로 사용
       - 공식: Σ(embedding * weight) / Σ(weight)
    
    4. calculateSimilarityScores(targetEmbedding, candidateEmbeddings) 메서드
       - 타겟 임베딩과 여러 후보 임베딩의 유사도 계산
       - 배열로 반환

    파일: client/src/services/recommendationService.js
    작업 내용:
    1. RecommendationService 클래스 생성
       - ModelLoader, EmbeddingService, SimilarityCalculator 의존성
    
    2. getTopLikedSongs(queue, musicLikes, topN) 메서드
       - 대기열에서 하트 높은 순으로 정렬
       - 상위 N개 선택
       - 좋아요 개수가 0인 음악도 포함 (가중치 낮게)
    
    3. generateRecommendations(queue, musicLikes, searchQuery?) 메서드
       - 전체 추천 로직 통합
       - 단계별 처리:
         a. 상위 하트 음악 선택
         b. 각 음악 제목 임베딩 생성
         c. 가중 평균 임베딩 계산
         d. YouTube 검색 결과 수집 (서버 또는 클라이언트)
         e. 검색 결과 임베딩 생성
         f. 유사도 계산
         g. 인기도 점수 계산 (YouTube Data API 또는 검색 순서)
         h. 추가 점수 계산 (아티스트, 인기도)
         i. 정렬 및 필터링
         i. 상위 N개 반환
    
    4. calculatePopularityScore(videoId, searchIndex) 메서드
      - 인기도 점수 계산
      - 방법 1: YouTube Data API로 조회수 가져오기 (1순위)
        * API 키가 있으면 조회수 기반 계산
        * 조회수 정규화 + 최신도 보너스
      - 방법 2: 검색 결과 순서 기반 (2순위, 폴백)
        * 검색 결과 index를 점수로 변환
        * 1-3위: 1.0, 4-5위: 0.9, 6-10위: 0.7, 11-20위: 0.5, 이후: 0.3
    
    5. calculateFinalScore(similarity, artistMatch, popularityScore) 메서드
      - 최종 점수 계산
      - 가중치: similarity(0.7), artistMatch(0.15), popularityScore(0.15)
    
    5. filterDuplicates(recommendations, queue) 메서드
       - 대기열에 이미 있는 음악 제거
       - videoId 기준으로 비교

         const queueData = queueManager.getQueue();
         const likesData = {};

         queueData.forEach(music => {
           const likeData = musicLikes.get(music.videoId);
           likesData[music.videoId] = likeData ? likeData.count : 0;
         });
         
         socket.emit('queueAndLikes', {
           queue: queueData,
           musicLikes: likesData
         });
       });

15. 제어권과의 관계
----------------------------------------
15.1. 제어권 독립성 확인
    브라우저 기반 AI 추천 기능은 제어권과 완전히 독립적으로 동작합니다.
    
    ✅ 제어권이 없는 사용자도 AI 추천 사용 가능
    ✅ 제어권이 옮겨져도 각 사용자의 브라우저에서 독립적으로 동작
    ✅ 추천 결과를 대기열에 추가하는 것도 제어권 불필요
    
    제어권이 필요한 기능:
    - 재생 제어 (pause, resume, playNext)
    - 대기열 관리 (removeFromQueue, reorderQueue)
    
    제어권 불필요한 기능:
    - AI 추천 기능 전체 (브라우저에서 실행)
    - 대기열에 음악 추가 (requestMusic)
    - 대기열 데이터 읽기 (getQueueAndLikes)

15.2. 다중 사용자 시나리오
    [시나리오] 여러 사용자가 동시에 AI 추천 사용
    1. 사용자 A: 제어권 보유, AI 추천 사용
       - 브라우저에서 모델 로드 및 추천 계산
       - 추천 결과를 대기열에 추가
       - 정상 동작 ✅
    
    2. 사용자 B: 제어권 없음, AI 추천 사용
       - 브라우저에서 모델 로드 및 추천 계산
       - 추천 결과를 대기열에 추가
       - 정상 동작 ✅
    
    3. 제어권이 사용자 A → 사용자 B로 이동
       - 사용자 A의 AI 추천 기능: 영향 없음 ✅
       - 사용자 B의 AI 추천 기능: 영향 없음 ✅
       - 각 사용자의 브라우저에서 독립적으로 동작

15.3. 구현 시 고려사항
    - 제어권 체크 불필요: AI 추천 관련 모든 기능은 제어권 체크 없이 구현
    - 서버 이벤트: 'getQueueAndLikes'는 모든 사용자에게 동일한 데이터 제공
    - 클라이언트 처리: 모든 AI 추천 로직은 브라우저에서 처리되므로 서버 제약 없음
    - 인기도 확인: YouTube Data API 키가 있으면 조회수 기반, 없으면 검색 순서 기반

16. 인기도 확인 방법 상세
----------------------------------------
16.1. YouTube Data API 조회수 기반 (1순위, 권장)
    구현 방법:
    1. YouTube Data API v3 사용
       - googleapis 라이브러리 설치
       - API 키 설정 (환경 변수)
    
    2. videos.list API 호출
       - videoId로 조회수, 발행일 가져오기
       - part: 'statistics,snippet'
       - fields: 'items(id,statistics(viewCount),snippet(publishedAt))'
    
    3. 인기도 점수 계산
       - 조회수 정규화: log(viewCount + 1) / log(maxViewCount + 1)
       - 최신도 계산: (현재날짜 - publishedAt) 기반
       - 최종 점수: 조회수 점수 × 0.7 + 최신도 점수 × 0.3
    
    4. 배치 처리
       - 여러 videoId를 한 번에 조회 (최대 50개)
       - API 할당량 절약
    
    예시 코드 구조:
    ```javascript
    // 서버: server/index.js
    const { google } = require('googleapis');
    const youtube = google.youtube('v3');
    
    socket.on('getVideoDetails', async (videoIds) => {
      try {
        const response = await youtube.videos.list({
          key: process.env.YOUTUBE_API_KEY,
          part: 'statistics,snippet',
          id: videoIds.join(',')
        });
        
        const details = response.data.items.map(item => ({
          videoId: item.id,
          viewCount: parseInt(item.statistics.viewCount || 0),
          publishedAt: item.snippet.publishedAt
        }));
        
        socket.emit('videoDetails', details);
      } catch (error) {
        // 폴백: 검색 순서 기반 사용
        socket.emit('videoDetailsError', { message: 'API 오류' });
      }
    });
    ```

16.2. 검색 결과 순서 기반 (2순위, 폴백)
    구현 방법:
    1. 검색 결과의 index 활용
       - YouTube 검색 API는 기본적으로 인기순 정렬
       - 검색 결과의 순서를 인기도로 간주
    
    2. 순서 → 점수 변환
       - 1-3위: 1.0 (최고 인기)
       - 4-5위: 0.9
       - 6-10위: 0.7
       - 11-20위: 0.5
       - 21위 이후: 0.3
    
    3. 구현
       - 검색 결과 배열의 index 사용
       - 별도 API 호출 불필요
    
    예시 코드:
    ```javascript
    function calculatePopularityByIndex(index) {
      if (index < 3) return 1.0;
      if (index < 5) return 0.9;
      if (index < 10) return 0.7;
      if (index < 20) return 0.5;
      return 0.3;
    }
    ```

16.3. 최종 점수 계산 (길이 제외)
    점수 구성:
    - 텍스트 유사도: 70%
    - 아티스트 일치: 15%
    - 인기도 보너스: 15%
    
    계산식:
    ```
    최종 점수 = (유사도 × 0.7) + (아티스트일치 × 0.15) + (인기도 × 0.15)
    
    예시:
    - 유사도: 0.9
    - 아티스트 일치: 1.0 (같은 아티스트)
    - 인기도: 0.8 (조회수 기반 또는 검색 순서)
    → 최종 점수 = (0.9 × 0.7) + (1.0 × 0.15) + (0.8 × 0.15) = 0.885
    ```

16.4. 구현 우선순위
    1. 검색 결과 순서 기반 구현 (간단, 폴백용)
    2. YouTube Data API 통합 (정확도 향상)
    3. 두 방법 모두 지원하되, API 키가 있으면 자동으로 조회수 기반 사용
