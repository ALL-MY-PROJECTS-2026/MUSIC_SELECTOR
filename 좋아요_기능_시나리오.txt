========================================
좋아요 기능 구현 시나리오
========================================

1. 클라이언트 측 (CurrentPlaying.jsx)
----------------------------------------
1.1. 하트 클릭 이벤트 처리
    - 사용자가 하트 아이콘 클릭
    - 현재 세션(socket.id)이 해당 음악에 이미 좋아요를 눌렀는지 확인
    - 좋아요를 누르지 않았다면:
      a. 로컬 상태 업데이트 (isLiked = true)
      b. 서버에 'likeMusic' 이벤트 전송
        - 전송 데이터: { videoId, title, socketId }
    - 이미 좋아요를 눌렀다면:
      - 클릭 무시 (중복 방지)

1.2. 좋아요 상태 초기화
    - 음악이 변경될 때 (music.videoId 변경)
    - localStorage에서 현재 세션의 좋아요 여부 확인
    - 좋아요를 눌렀던 음악이면 isLiked = true로 설정
    - 좋아요를 누르지 않았던 음악이면 isLiked = false로 설정

1.3. localStorage 구조
    - 키: 'musicLikes'
    - 값: JSON 객체
      {
        "likesByVideoId": {
          "videoId1": {
            "count": 5,
            "likedSessions": ["socketId1", "socketId2", "socketId3", "socketId4", "socketId5"]
          },
          "videoId2": {
            "count": 2,
            "likedSessions": ["socketId1", "socketId2"]
          }
        },
        "sessionLikes": {
          "socketId1": ["videoId1", "videoId2"],
          "socketId2": ["videoId1", "videoId2"]
        }
      }

1.4. 좋아요 개수 표시
    - 하트 아이콘 우측 상단에 좋아요 개수 숫자로 표시
    - 서버에서 받은 좋아요 개수 정보 사용
    - 배지 형태로 표시 (작은 원형 배경에 숫자)
    - 좋아요 개수가 0이면 배지 숨김
    - 좋아요 개수가 1 이상이면 배지 표시

2. 서버 측 (server/index.js)
----------------------------------------
2.1. 좋아요 이벤트 수신
    - socket.on('likeMusic', (data) => { ... })
    - 수신 데이터: { videoId, title, socketId }
    - 처리 로직:
      a. 좋아요 데이터 저장소 확인/생성
      b. 해당 세션이 이미 좋아요를 눌렀는지 확인
      c. 좋아요를 누르지 않았다면:
         - 좋아요 개수 증가
         - 세션 ID를 좋아요 목록에 추가
         - localStorage 업데이트 (서버 측 저장소에 반영)
      d. 모든 클라이언트에 'likeUpdated' 이벤트 전송
        - 전송 데이터: { videoId, count, likedSessions }

2.2. 서버 측 좋아요 데이터 저장소
    - 메모리 기반 저장소 (Map 또는 객체)
    - 구조:
      {
        "videoId1": {
          "title": "노래 제목",
          "count": 5,
          "likedSessions": ["socketId1", "socketId2", ...]
        },
        "videoId2": { ... }
      }

2.3. 좋아요 개수 조회
    - socket.on('getLikeCount', (videoId) => { ... })
    - 해당 videoId의 좋아요 개수 반환
    - 전송: socket.emit('likeCount', { videoId, count })

2.4. 세션별 좋아요 여부 확인
    - socket.on('checkLiked', (videoId) => { ... })
    - 해당 세션이 해당 음악에 좋아요를 눌렀는지 확인
    - 전송: socket.emit('likedStatus', { videoId, isLiked })

3. 플레이리스트 CRUD 기능 (제어권 필수)
----------------------------------------
3.1. 큐 관리자 확장 (queueManager.js)
    - getQueueSortedByLikes() 메서드 추가
    - 좋아요 개수 기준 내림차순 정렬
    - 좋아요 개수가 같으면 원래 순서 유지
    - createPlaylist(name, musicList) - 플레이리스트 생성
    - readPlaylist(playlistId) - 플레이리스트 조회
    - updatePlaylist(playlistId, updates) - 플레이리스트 수정
    - deletePlaylist(playlistId) - 플레이리스트 삭제
    - addMusicToPlaylist(playlistId, music) - 플레이리스트에 음악 추가
    - removeMusicFromPlaylist(playlistId, musicId) - 플레이리스트에서 음악 제거
    - reorderPlaylist(playlistId, fromIndex, toIndex) - 플레이리스트 순서 변경

3.2. 서버 측 CRUD API (제어권 체크 필수)
    - socket.on('createPlaylist', (data) => { ... })
      * 제어권 확인: controlSessionId === socket.id
      * 제어권 없으면 에러 반환
      * 플레이리스트 생성 후 모든 클라이언트에 브로드캐스트
    - socket.on('readPlaylist', (playlistId) => { ... })
      * 제어권 확인 필수
      * 플레이리스트 정보 반환
    - socket.on('updatePlaylist', (data) => { ... })
      * 제어권 확인 필수
      * 플레이리스트 수정 후 브로드캐스트
    - socket.on('deletePlaylist', (playlistId) => { ... })
      * 제어권 확인 필수
      * 플레이리스트 삭제 후 브로드캐스트
    - socket.on('addMusicToPlaylist', (data) => { ... })
      * 제어권 확인 필수
      * 음악 추가 후 브로드캐스트
    - socket.on('removeMusicFromPlaylist', (data) => { ... })
      * 제어권 확인 필수
      * 음악 제거 후 브로드캐스트
    - socket.on('reorderPlaylist', (data) => { ... })
      * 제어권 확인 필수
      * 순서 변경 후 브로드캐스트
    - socket.on('getQueueSortedByLikes', () => { ... })
      * 제어권 확인 필수
      * 좋아요 개수 기준으로 정렬된 큐 반환
      * 전송: socket.emit('queueSortedByLikes', sortedQueue)

3.3. 클라이언트 측 CRUD 요청 (제어권 체크)
    - App.js에서 hasControl 상태 확인
    - 제어권이 있을 때만 CRUD 버튼 표시
    - 제어권이 없으면 버튼 비활성화 또는 숨김
    - QueueList 컴포넌트에서 제어권에 따른 UI 제어
    - 플레이리스트 관리 UI 추가 (제어권 있을 때만 표시)

3.4. 플레이리스트 데이터 구조
    - 서버 측 저장소:
      {
        "playlistId1": {
          "name": "플레이리스트 이름",
          "createdAt": "2024-01-01T00:00:00Z",
          "updatedAt": "2024-01-01T00:00:00Z",
          "musicList": [
            { "id": "musicId1", "videoId": "videoId1", "title": "노래 제목", ... },
            { "id": "musicId2", "videoId": "videoId2", "title": "노래 제목", ... }
          ],
          "likeCount": 5,
          "sortedByLikes": false
        }
      }
    - localStorage 구조:
      {
        "playlists": {
          "playlistId1": { ... },
          "playlistId2": { ... }
        },
        "currentPlaylist": "playlistId1"
      }

4. 데이터 흐름
----------------------------------------
4.1. 좋아요 클릭 시:
    클라이언트 (CurrentPlaying.jsx)
      ↓
    하트 클릭 → isLiked 상태 확인
      ↓
    좋아요 안 눌렀음 → 서버에 'likeMusic' 이벤트 전송
      ↓
    서버 (server/index.js)
      ↓
    좋아요 데이터 업데이트 (개수 증가, 세션 추가)
      ↓
    모든 클라이언트에 'likeUpdated' 브로드캐스트
      ↓
    클라이언트 (App.js)
      ↓
    localStorage 업데이트
      ↓
    CurrentPlaying 컴포넌트에 좋아요 개수 전달

4.2. 음악 변경 시:
    새로운 음악 재생
      ↓
    CurrentPlaying.jsx에서 music.videoId 변경 감지
      ↓
    서버에 'checkLiked' 이벤트 전송 (videoId)
      ↓
    서버에서 해당 세션의 좋아요 여부 확인
      ↓
    'likedStatus' 이벤트로 응답
      ↓
    CurrentPlaying.jsx에서 isLiked 상태 업데이트

4.3. 플레이리스트 조회 시:
    클라이언트에서 정렬된 큐 요청 (제어권 확인)
      ↓
    hasControl === true 확인
      ↓
    서버에 'getQueueSortedByLikes' 이벤트 전송
      ↓
    서버에서 제어권 확인 (controlSessionId === socket.id)
      ↓
    제어권 있음 → 좋아요 개수 기준 정렬
      ↓
    'queueSortedByLikes' 이벤트로 정렬된 큐 전송
      ↓
    QueueList 컴포넌트에서 정렬된 큐 표시
    제어권 없음 → 에러 메시지 반환

4.4. 플레이리스트 생성 시:
    클라이언트에서 플레이리스트 생성 요청 (제어권 확인)
      ↓
    hasControl === true 확인
      ↓
    서버에 'createPlaylist' 이벤트 전송
      ↓
    서버에서 제어권 확인
      ↓
    제어권 있음 → 플레이리스트 생성
      ↓
    모든 클라이언트에 'playlistCreated' 브로드캐스트
      ↓
    클라이언트에서 localStorage 업데이트

4.5. 플레이리스트 수정 시:
    클라이언트에서 플레이리스트 수정 요청 (제어권 확인)
      ↓
    hasControl === true 확인
      ↓
    서버에 'updatePlaylist' 이벤트 전송
      ↓
    서버에서 제어권 확인
      ↓
    제어권 있음 → 플레이리스트 수정
      ↓
    모든 클라이언트에 'playlistUpdated' 브로드캐스트
      ↓
    클라이언트에서 localStorage 업데이트

4.6. 플레이리스트 삭제 시:
    클라이언트에서 플레이리스트 삭제 요청 (제어권 확인)
      ↓
    hasControl === true 확인
      ↓
    서버에 'deletePlaylist' 이벤트 전송

8. 제어권 체크 패턴
----------------------------------------
8.1. 서버 측 제어권 체크 함수
    function checkControl(socketId) {
      if (controlSessionId !== socketId) {
        return { hasControl: false, error: '제어권이 없습니다.' };
      }
      return { hasControl: true };
    }

8.2. 서버 측 이벤트 핸들러 패턴
    socket.on('someEvent', (data) => {
      const controlCheck = checkControl(socket.id);
      if (!controlCheck.hasControl) {
        socket.emit('error', { message: controlCheck.error });
        return;
      }
      // 제어권이 있을 때만 실행
      // ... 실제 로직 ...
    });

8.3. 클라이언트 측 제어권 체크 패턴
    const handleSomeAction = () => {
      if (!hasControl) {
        alert('제어권이 없습니다.');
        return;
      }
      // 제어권이 있을 때만 실행
      socket.emit('someEvent', data);
    };

8.4. UI 제어 패턴
    {hasControl && (
      <button onClick={handleSomeAction}>작업 수행</button>
    )}
    또는
    <button 
      onClick={handleSomeAction}
      disabled={!hasControl}
    >
      작업 수행
    </button>

9. 주의사항
----------------------------------------
- 세션 ID는 socket.id를 사용 (재연결 시 변경됨)
- 같은 사용자가 재연결하면 새로운 세션으로 간주
- 좋아요 데이터는 서버 메모리에 저장 (서버 재시작 시 초기화)
- 플레이리스트 데이터도 서버 메모리에 저장 (서버 재시작 시 초기화)
- 영구 저장이 필요하면 데이터베이스 연동 필요
- localStorage는 클라이언트별로 독립적
- 서버 측 데이터가 최종 기준
- 모든 플레이리스트 CRUD 작업은 제어권이 있는 세션에서만 가능
- 제어권이 없는 세션은 조회만 가능 (선택사항)
- 제어권이 없는 세션에서 CRUD 요청 시 에러 반환
