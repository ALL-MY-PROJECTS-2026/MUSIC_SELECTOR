================================================================================
비디오 재생 멈춤 문제 원인 분석 및 수정 시나리오
================================================================================

【문제 1】 정지 버튼 누르고 다시 시작 버튼 누르면 계속 멈춤 현상 발생
【문제 2】 재생 위치 바꿔도 멈추는 문제 발생

================================================================================
1. 문제 원인 분석
================================================================================

【문제 1 원인: 정지 후 재생 시 멈춤 현상】

1.1 handleResume 함수의 문제점 (1528-1620줄)
   - handleResume에서 pauseTimeRef.current를 null로 초기화하고 재생을 시도함
   - 하지만 재생 상태 동기화 useEffect (1623줄)가 실행될 때 타이밍 문제 발생
   - pauseTimeRef.current가 null로 설정되기 전에 useEffect가 실행되면 재생이 막힘

1.2 재생 상태 동기화 useEffect의 문제점 (1623-1919줄)
   - 1751줄: pauseTimeRef.current !== null이면 자동 재생하지 않음
   - 1734-1737줄: 서버가 재생 중이면 pauseTimeRef를 초기화하지만, 
     handleResume 호출 직후에는 아직 서버 상태가 업데이트되지 않았을 수 있음
   - 1801-1874줄: 서버가 일시정지 상태(!isPlaying)이면 pauseTimeRef를 설정하여 재생을 막음
   - handleResume에서 onResume()을 호출하지만, 서버 상태 업데이트가 비동기적으로 이루어짐
   - 따라서 handleResume에서 재생을 시도해도 useEffect가 다시 pauseTimeRef를 설정하여 멈춤

1.3 onStateChange 이벤트 핸들러의 문제점 (1009-1095줄)
   - 1009줄: PAUSED 상태일 때 pauseTimeRef.current를 설정
   - 1082-1094줄: 서버가 재생 중인데 플레이어가 일시정지 상태이면 자동 재생 시도
   - 하지만 pauseTimeRef.current가 null이 아니면 재생하지 않음
   - handleResume에서 재생을 시도해도, onStateChange에서 PAUSED 상태를 감지하면 
     pauseTimeRef를 다시 설정할 수 있음

【문제 2 원인: 재생 위치 변경 시 멈춤 현상】

2.1 seek 감지 및 동기화 로직의 문제점 (2156-2267줄)
   - 2169-2208줄: seek 감지 후 서버로 전송
   - 2287-2352줄: seek 이벤트 수신 시 seekTo 호출
   - 하지만 seekTo 호출 후 자동 재생이 제대로 작동하지 않을 수 있음

2.2 재생 상태 동기화 useEffect와의 충돌
   - seekTo 호출 후 플레이어가 PAUSED 상태가 될 수 있음
   - 재생 상태 동기화 useEffect에서 pauseTimeRef.current가 설정되어 있으면 재생하지 않음
   - seek 후 자동 재생이 필요한데 pauseTimeRef 때문에 막힘

2.3 onStateChange에서 seek 후 재생 처리 부족
   - seekTo 호출 시 onStateChange 이벤트가 발생하지만
   - seek 후 자동 재생을 보장하는 로직이 부족함

================================================================================
2. 수정 시나리오
================================================================================

【수정 1】 handleResume 함수 개선

위치: 1495-1620줄 (handleResume 함수)

변경 사항:
1. pauseTimeRef.current를 null로 초기화한 후, 재생 상태 동기화 useEffect가 
   실행되기 전에 재생을 시도하도록 보장
2. 재생 시도 전에 lastPlayAttemptRef.current를 설정하여 
   재생 상태 동기화 useEffect가 재생을 막지 않도록 함
3. seekTo 호출 후 재생 시도 시 플레이어 상태를 확인하고, 
   PAUSED 상태이면 명시적으로 playVideo() 호출
4. 재생 시도 후 짧은 지연을 두고 플레이어 상태를 확인하여 
   재생이 시작되었는지 검증

구체적 수정:
- 1528줄: pauseTimeRef.current를 null로 초기화
- 1531줄: lastPlayAttemptRef.current를 null로 리셋 (재생 시도 시간 초기화)
- 1564-1593줄: savedPauseTime이 있을 때 seekTo 후 재생 시도 로직 개선
   * seekTo 호출 후 플레이어 상태 확인
   * PAUSED 상태이면 명시적으로 playVideo() 호출
   * 재생 시도 후 상태 검증 추가
- 1594-1611줄: savedPauseTime이 없을 때도 재생 시도 로직 개선
   * 플레이어 상태 확인 후 재생 시도
   * 재생 시도 후 상태 검증 추가

【수정 2】 재생 상태 동기화 useEffect 개선

위치: 1623-1919줄 (재생 상태 동기화 useEffect)

변경 사항:
1. handleResume에서 재생을 시도한 경우를 감지하여 pauseTimeRef를 초기화
2. lastPlayAttemptRef.current가 최근에 설정되었으면 (예: 2초 이내) 
   pauseTimeRef를 초기화하여 재생을 허용
3. 서버 상태 업데이트 대기 시간을 고려하여 재생을 막지 않도록 함

구체적 수정:
- 1732-1754줄: 재생 조건 확인 로직 개선
   * lastPlayAttemptRef.current가 최근에 설정되었으면 (2초 이내) 
     pauseTimeRef를 초기화하여 재생 허용
   * handleResume에서 재생을 시도한 경우를 명시적으로 처리
- 1756-1797줄: 재생 시도 로직 개선
   * 재생 시도 전에 pauseTimeRef가 null인지 다시 확인
   * 재생 시도 후 상태 검증 로직 개선

【수정 3】 onStateChange 이벤트 핸들러 개선

위치: 1009-1095줄 (onStateChange의 PAUSED 상태 처리)

변경 사항:
1. handleResume에서 재생을 시도한 경우를 감지하여 pauseTimeRef를 설정하지 않음
2. lastPlayAttemptRef.current가 최근에 설정되었으면 (예: 2초 이내) 
   pauseTimeRef를 설정하지 않음
3. seekTo 호출 후 발생하는 PAUSED 상태는 무시하거나 
   자동으로 재생을 시도하도록 함

구체적 수정:
- 1009-1077줄: PAUSED 상태 처리 로직 개선
   * lastPlayAttemptRef.current가 최근에 설정되었으면 (2초 이내) 
     pauseTimeRef를 설정하지 않음
   * handleResume에서 재생을 시도한 경우를 명시적으로 처리
- 1082-1094줄: 자동 재생 시도 로직 개선
   * pauseTimeRef가 null인지 확인 후 재생 시도
   * 재생 시도 후 상태 검증 추가

【수정 4】 seek 감지 및 동기화 로직 개선

위치: 2287-2352줄 (handlePlaybackPositionSeek 함수)

변경 사항:
1. seekTo 호출 후 자동 재생을 보장
2. seekTo 호출 후 pauseTimeRef를 초기화하여 재생을 허용
3. seekTo 호출 후 플레이어 상태를 확인하고, 
   PAUSED 상태이면 명시적으로 playVideo() 호출

구체적 수정:
- 2322-2344줄: seekTo 호출 후 재생 처리 로직 개선
   * seekTo 호출 전에 pauseTimeRef를 null로 초기화
   * seekTo 호출 후 플레이어 상태 확인
   * PAUSED 상태이면 명시적으로 playVideo() 호출
   * 재생 시도 후 상태 검증 추가

【수정 5】 재생 위치 전송 인터벌에서 seek 후 재생 처리

위치: 2210-2243줄 (재생 위치 전송 인터벌)

변경 사항:
1. seek 감지 후 재생 위치를 전송할 때, 
   플레이어가 PAUSED 상태이면 자동으로 재생 시도
2. pauseTimeRef를 확인하여 재생을 허용

구체적 수정:
- 2216-2226줄: 백그라운드에서 일시정지 감지 로직 개선
   * pauseTimeRef가 null인지 확인 후 재생 시도
   * seek 후 발생하는 PAUSED 상태도 처리

4. 예상 효과
================================================================================

1. 정지 버튼 누르고 다시 시작 버튼 누르면 정상적으로 재생됨
2. 재생 위치를 바꿔도 멈추지 않고 정상적으로 재생됨
3. 재생 상태 동기화 로직이 더 안정적으로 작동함
4. seek 후 자동 재생이 보장됨

================================================================================
5. 주의사항
================================================================================

1. pauseTimeRef와 lastPlayAttemptRef의 타이밍 문제를 주의깊게 처리해야 함
2. 서버 상태 업데이트와 클라이언트 재생 시도의 타이밍을 고려해야 함
3. onStateChange 이벤트와 useEffect의 실행 순서를 고려해야 함
4. seekTo 호출 후 플레이어 상태 변경을 고려해야 함
5. 테스트 시 다양한 시나리오를 확인해야 함:
   - 정지 후 재생
   - 재생 중 정지 후 재생
   - 재생 위치 변경
   - 재생 위치 변경 후 정지 및 재생
   - 여러 클라이언트에서 동시에 제어하는 경우

6. 추가 개선 사항 (선택사항)
================================================================================

1. 재생 상태 플래그 추가
   - isResumingRef 같은 플래그를 추가하여 handleResume에서 재생을 시도하는 중임을 표시
   - 재생 상태 동기화 useEffect에서 이 플래그를 확인하여 pauseTimeRef를 설정하지 않음

2. 재생 시도 재시도 로직 개선
   - 재생 시도가 실패하면 자동으로 재시도하는 로직 추가
   - 최대 재시도 횟수 제한

3. 로깅 개선
   - 재생 상태 변경 시 상세한 로그 추가
   - 디버깅을 위한 로그 레벨 조정
